# plot_lmtad_results — Reference

This document describes the `tools/plot_lmtad_results.py` plotting utility added to the HOSER repository. It explains how to run the tool, interpretation of outputs, and the statistical calculations used for the abnormality (outlier) bar chart including the error bars.

## Purpose

- Produce publication-ready visualizations of LM‑TAD evaluation outputs produced by `tools/evaluate_dataset_with_lmtad.py` (or `simple_evaluate_with_lmtad.py`) for quick exploration and reporting.
- Support reproducible research by documenting exactly how each figure and summary value is computed.

## Input

The tool reads results from an evaluation directory created by the evaluation tooling. It looks for either (in order):

- `evaluation_results.json` — aggregated JSON file where keys are split names (`train`, `val`, `test`, etc.) and values are result objects generated by the evaluation script.
- `evaluation_results.jsonl` — one JSON object per line; each object should contain `{"split": <split_name>, "results": {...}}`.

Each split's `results` object is expected to contain at least the following fields (these are written by `evaluate_dataset_with_lmtad.py`):

- `num_trajectories`: integer (number of evaluated trajectories in that split)
- `log_perplexity_values`: array of numeric log‑perplexity values (may contain `inf` for failed trajectories)
- `outlier_rate`: fraction in [0,1] representing the outlier fraction computed during evaluation (the tool will convert this to percentage for plotting)

If `outlier_rate` is missing for a split, the plotting tool will compute visuals from the `log_perplexity_values`, but the abnormality CSV will leave the field blank.

## Command line usage

Basic usage:

```bash
python tools/plot_lmtad_results.py \
  --eval-dir tools_eval_lmtad/Beijing_abnormal \
  --out plots/lmtad_eval
```

- `--eval-dir`: Path to the evaluation directory that contains `evaluation_results.json` or `evaluation_results.jsonl`.
- `--out`: Output path. If this argument is a directory the tool will write files into it with base name `lmtad_eval`. If it contains a filename stem (e.g. `plots/lmtad`), that stem is used to build filenames. If the path has no suffix and doesn't exist it is treated as a directory and will be created.
- `--show`: Optional — show the boxplot interactively after saving files.

## Output files

The tool writes the following files into the selected output directory (constructed from the `--out` argument):

- `<base>_<split>.png` — histogram of log‑perplexities for `<split>` with a dashed vertical line showing the 95th percentile threshold used during evaluation.
- `<base>_boxplot.png` — combined boxplot comparing log‑perplexity distributions across splits.
- `<base>_abnormality.png` — bar chart showing abnormality (outlier) percentage per split with error bars (standard error) and numeric labels above each bar.
- `<base>_abnormality.csv` — CSV summary containing per‑split numeric values and standard errors. Columns:
  - `split` — split name
  - `num_trajectories` — number of trajectories used to compute the rate
  - `outlier_rate_fraction` — outlier fraction (0–1) or blank if not available
  - `outlier_rate_percent` — outlier percentage (0–100) or blank
  - `outlier_rate_se_percent` — standard error of the percentage (in percentage points)

Files are overwritten if already present.

## Computation details and interpretation

### Outlier labeling in evaluation

The evaluation code marks a trajectory as an outlier when its log‑perplexity is strictly greater than the 95th percentile of the per‑trajectory scores for that split. Concretely (reproduced here):

1. Collect `all_outlier_scores` (these are the log‑perplexity values assigned to each evaluated trajectory). Note: evaluation can mark problematic trajectories with `inf` when evaluation failed; these should be handled carefully.
2. Compute `threshold = np.percentile(all_outlier_scores, 95)`.
3. Label outliers with `1` where `score > threshold`, otherwise `0`.

Because the cutoff is a percentile, the expected fraction labeled `1` will be approximately 5% of the dataset (but not always exactly 5% due to ties, discrete sample sizes, and presence of `inf` values which influence the percentile computation).

### Abnormality bar chart and standard error (error bars)

The abnormality bar chart (`<base>_abnormality.png`) visualizes the `outlier_rate` (converted to percent) for each split. The error bars show the standard error (SE) of a proportion, computed per split using the standard binomial approximation:

Let p be the observed fraction (0–1) and n the number of independent trajectories used. Then the standard error of the fraction is:

    SE_frac = sqrt( p * (1 - p) / n )

To plot this as percentage points (so the y axis is in %), we multiply by 100:

    SE_percent = SE_frac * 100 = sqrt( p * (1 - p) / n ) * 100

Notes and assumptions:

- This SE assumes each trajectory is an independent Bernoulli trial with probability p of being labeled an outlier. This is an approximation — in practice there may be dependencies between trajectories (spatial/temporal clustering), which would make SE optimistic (underestimate true variance).
- For small n, or when p is very close to 0 or 1, the normal approximation can be poor. In those cases consider exact binomial confidence intervals (Clopper–Pearson) or bootstrap methods.
- The plotting tool still shows SE even for very small p; the CSV includes the raw SE so you can compute a 95% approximate confidence interval as p_percent ± 1.96 * SE_percent.

Example: if `outlier_rate = 0.05` (5%) and `n = 1000`, then

    SE_percent = sqrt(0.05 * 0.95 / 1000) * 100 ≈ 0.688%

An approximate 95% CI for the percent: 5% ± 1.96 * 0.688% ≈ [3.66%, 6.34%].

### Histograms and 95th percentile line

- Histograms are computed on the finite `log_perplexity_values` for the split (non‑finite values such as `inf` are excluded from the histogram and percentile computation).
- The vertical dashed red line marks the 95th percentile of the finite values shown. This matches the logic used by the evaluation pipeline to label outliers.

## Reproducibility notes

- If your evaluation used sampling (`--sample-frac`) or randomized operations, make sure to record the `sample_seed` so plots can be reproduced. The plotting tool uses only produced results files and does not re-run sampling.
- The CSV summary contains the numeric values necessary to reproduce the plotted bars and error bars exactly.

## Caveats & recommendations for research use

- When reporting abnormality rates, always state whether they were computed on sampled subsets (and the sampling fraction/seed) or on the full datasets.
- For formal hypothesis testing or tight confidence intervals, prefer exact binomial intervals or bootstrap confidence intervals over the normal approximation when n is small or when p is near 0/1.
- If many evaluation runs report identical log‑perplexities or the same `inf` placeholder for failures, check your evaluation pipeline for failures that may bias the percentile computation.

## Example workflow

1. Run evaluation (example):

```bash
uv run python tools/evaluate_dataset_with_lmtad.py \
  --dataset Beijing_abnormal \
  --data-dir data/Beijing_abnormal \
  --roadmap data/Beijing/roadmap.geo \
  --lmtad-checkpoint /path/to/ckpt_best.pt \
  --sample-frac 0.01 --sample-seed 42
```

2. Plot results:

```bash
python tools/plot_lmtad_results.py --eval-dir tools_eval_lmtad/Beijing_abnormal --out plots/lmtad_eval
```

3. Inspect `plots/lmtad_eval_abnormality.csv` for per‑split numeric values and SEs.

## Implementation notes (developer reference)

- The plotting script loads aggregated `evaluation_results.json` when present, otherwise reads `evaluation_results.jsonl`.
- The `outlier_rate` used is taken directly from the results file when available. The plotting script multiplies the fraction by 100 for display.
- SE calculation and annotation use `numpy` and `matplotlib`.
